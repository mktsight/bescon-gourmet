# ベスコングルメ部 開催案内フライヤー（bescon-flyer）

「運動で整える → 最高のコンディション → ご褒美の美味しい食事」というコンセプトの開催案内を、既存4枚と同じデザインで作るためのスキル。デザインはスクリプトが固定で描くので、エージェントの仕事は「最小入力から JSON 仕様を作ること」と「イラスト（運動シーンとご褒美の一皿）を用意すること」の2つだけ。

参照ファイル（必要になったときに読む）:

- [references/spec.md](references/spec.md) … JSON 仕様の全キー（必須／任意／既定値／導出）、自動調整、終了コード
- [references/derivation.md](references/derivation.md) … ローマ字・キャッチコピー・テーマ色・METs・持ち物・当日の流れ・注記の導出ルール
- [references/illustration.md](references/illustration.md) … イラストのスニペット API、座標契約、スタイルガイド
- `examples/` … 既存4枚の仕様（yamadera / zao / kaminoyama / ekimae）と、最小入力からの導出例 minimal-example.json
- `illustrations/scenes/_template.js`、`illustrations/rewards/_template.js` … 新しいイラストの雛形

## 1. 概要と出力

- 仕様: `<ワークスペース>/flyer-specs/BCG企画_〇〇編.json`（後から編集して再生成できるよう必ず保存する）
- 出力: ワークスペース直下の `BCG企画_〇〇編.svg` と `BCG企画_〇〇編.png`（1800×2400、sips で変換）
- SVG の `<title>` はファイルのベース名（`BCG企画_〇〇編`）と同じ。ジェネレーターが自動で入れる
- タイトルは「〇〇編」が大きなアクセント、「第N回 ベスコングルメ部」は控えめな小見出し（デザインは固定なので触らない）
- 生成スクリプトは Node.js 標準ライブラリのみ（npm 不要）。PNG 化は macOS の `sips`

## 2. 最小入力

必須（ユーザーから聞く6項目）:

| 項目 | 例 |
|---|---|
| 編名 | 天童（「編」は付けても付けなくてもよい） |
| 開催日 | 2027-02-13 |
| 集合時刻 | 10:00 |
| 集合場所 | 天童駅 |
| 運動内容 | 舞鶴山ハイキング |
| ご褒美の食事 | 天童温泉の将棋の駒そば |

任意（言われなければ既定値・導出値を使う）:

| 項目 | 既定 |
|---|---|
| 回数 | 1（`第1回`・`Vol.01`） |
| 幹事 | 部長 |
| 連絡先文言 | 参加可否はこちらまで |
| 持ち物 | 運動内容と季節から導出 |
| 注意事項（caution の赤い ⚠ 表示） | 冬・山・天候リスクがあれば true |
| テーマ色 | 未使用のパレットから選ぶ |
| 当日の流れの上書き | 集合時刻から5ステップを組み立てる |
| 消費カロリーの上書き | METs × 時間から計算 |

必須項目が欠けているときは、足りない項目だけを1回のメッセージでまとめて聞く。揃っていれば質問せずに進める。

## 3. 導出するもの

詳細は [references/derivation.md](references/derivation.md)。

- エリアのローマ字（`area_romaji`）… ヘボン式・大文字・長音省略（例 TENDO）
- キャッチコピー（`subtitle`）…「{場所}の{対象}を{動詞て形}、整った体で{ご褒美}と乾杯」
- テーマ色（`theme`）… `--themes` で未使用のパレットを確認し、季節や土地に合うものを理由付きで選ぶ
- 消費カロリー（`kcal_basis`）… METs 表と運動時間から。必ず「METs × 時間」の根拠をユーザーに示す
- 持ち物・当日の流れ・注記（予約、営業時間・定休日は要確認）
- 曜日は**ジェネレーターが日付から計算する**。日時行・ヘッダーの `SAT` などを手で書かない（`overview.date.value` を手書きすると曜日が違う場合にエラーになる）

ジェネレーターが自動で作るもの: 曜日、日時行（`2027年2月13日（土）10:00集合`）、ヘッダーの年・`02.13`・`SAT  10:00 START`、`第N回`・`Vol.NN`、kcal、シーン既定の点線（trail）、フッター、`<title>`、ファイル名、はみ出し時の縮小・改行。

## 4. 手順

コマンドはすべてワークスペース直下で実行する（パスはワークスペース相対）。

1. **入力を集める。** 必須6項目を確認し、欠けている分だけまとめて聞く。

2. **お店を Web 検索する。** ご褒美の店名・場所・営業形態を確認する。確認できた事実だけを書き、注記に「営業時間・定休日は要確認」を必ず入れる。見つからない・架空の店のときも、その旨をユーザーに伝え、注記で要確認とする。

3. **残りを導出する。** [references/derivation.md](references/derivation.md) に従い、ローマ字・キャッチコピー・METs と時間・持ち物・当日の流れ・注記・caution を決める。

4. **テーマ色の使用状況を確認する。**

   ```
   node .kiro/skills/bescon-flyer/scripts/build.js --themes .
   ```

   「未使用」のパレットから選び、選んだ理由（季節・土地の色）を控えておく。

5. **仕様 JSON を書く。** `examples/` の一番近いもの（最小入力からなら `examples/minimal-example.json`）をコピーして `flyer-specs/BCG企画_〇〇編.json` に保存し、書き換える。キーの意味は [references/spec.md](references/spec.md)。`_` で始まるキーはコメントとして無視されるので、導出の根拠を `_derived` などに残してよい。

6. **イラストを用意する。** 内蔵の一覧を確認する。

   ```
   node .kiro/skills/bescon-flyer/scripts/build.js --list
   ```

   - 同じ場所・同じ料理なら内蔵 id（例 `"scene": "zao"`, `"reward": "beef"`）を再利用してよい。
   - 新しい場所・料理なら、`illustrations/scenes/_template.js` と `illustrations/rewards/_template.js` をコピーして `flyer-specs/` に置き（例 `flyer-specs/tendo_scene.js`）、[references/illustration.md](references/illustration.md) の座標契約とスタイルガイドに従って描く。仕様では `"scene": "tendo_scene.js"` のように仕様ファイルからの相対パスで指定する。
   - ユーザーが気に入ったら `illustrations/scenes/<id>.js` などに昇格して次回から id で使えるようにする（id は英小文字・数字・`-`・`_`）。

7. **描画する。**

   ```
   node .kiro/skills/bescon-flyer/scripts/build.js flyer-specs/BCG企画_〇〇編.json --out . --png
   ```

   出力には曜日・日時行・ヘッダー・kcal の計算式・自動調整の内容が表示される。終了コード 1 は仕様エラー、3 はレイアウトに収まらない（何も書き出さない）、4 は同名ファイルが既にある（`--force` なし）。メッセージに出たフィールドを直して再実行する。

8. **PNG を read_file で開いて目視確認する（必須）。** 確認せずに完了報告しない。チェックリスト:

   - [ ] 文字の重なり・はみ出し・不自然な折返しがない（タイトル、キャッチコピー、開催概要の各行と右寄せ注記、注記帯、当日の流れのラベル、フッター）
   - [ ] 曜日が正しい（日時行の（土）とヘッダーの SAT が一致し、実際の暦どおり）
   - [ ] 消費カロリーの数値が導出どおり
   - [ ] 白い点線（trail）が運動する3人の近くから始まり、ご褒美の円の左端で終わっている
   - [ ] 人物や重要なモチーフが下中央のカロリーバッジ（x 246–610、y 300 より下）と干渉していない
   - [ ] ご褒美の円の中が料理と飲み物で埋まり、端に隙間がない。REWARD ラベルが読める
   - [ ] 運動シーンに3人（赤・青・緑のジャケット）が描かれ、季節感が合っている

9. **直して再描画する。** 問題があれば仕様やイラストを直し、同じ出力先に `--force` を付けて再生成し、もう一度 PNG を確認する。チェックリストがすべて通るまで繰り返す。

10. **日本語の平文で報告する。** 出力ファイル名、導出した値（ローマ字、キャッチコピー、テーマ色と理由、METs × 時間 → kcal、持ち物、当日の流れ）、お店の確認結果と要確認事項、ユーザーに確認してほしい点を伝える。

## 5. 既存4枚の更新

既存4枚（山寺編・蔵王ライザ編・上山編・山形駅前編）を直すときは:

1. `examples/<id>.json`（yamadera / zao / kaminoyama / ekimae）を `flyer-specs/BCG企画_〇〇編.json` にコピーして編集する。
2. まず `--out` に一時ディレクトリ（例 `/tmp/bescon-preview`）を指定して描画し、PNG を確認する。
3. ユーザーに確認を取ってから、ワークスペース直下へ `--force` 付きで上書きする。

examples をそのまま描画すると既存4枚とバイト単位で同じ SVG/PNG になる。

## 6. ルール

- **チャットのコードブロックに日本語を入れない**（Kiro では文字化けして豆腐になる）。コマンドを見せるときは日本語を含まない形にするか、文章で説明する。報告は平文で書く。
- **写真やラスター画像を埋め込まない**（`<image>` 禁止）。イラストはすべて SVG のベクターで描く。
- `旧デザイン/` と既存の `BCG企画_*編.svg/.png` は、ユーザーの確認と `--force` なしに変更しない。
- `dy` を使わない（sips で描画されない）。ジェネレーターはすべての行に x/y を書く。`filter`、tspan の装飾、`font-weight="bold"`（600 を使う）も使わない。
- 曜日・日時行・kcal を手で書かない。ジェネレーターに計算させる。
- 店情報は Web 検索で確かめ、営業時間・定休日は「要確認」と書く。
- レイアウト（色の当て方、配置、文字サイズ）はスクリプトに固定されている。変えたいと言われたら、全フライヤーに影響することを伝えてから相談する。

## 7. イラスト スタイルガイド（要約）

詳細と座標は [references/illustration.md](references/illustration.md)。

- **奥行きのレイヤー:** 空と日差し → 遠くの稜線 → 霧 → 中景 → 近景の地面 → 人物 → 手前の木などのフレーミング
- **空気遠近法:** 遠いものほど色を霧の色（FOG）に `mix` して淡くする
- **リアルな人物:** 7.5頭身（`ctx.people.sideFigure` / `backFigure`）。3人のジャケットは赤 `#b8432f`・青 `#3a5f8f`・緑 `#3f7a55`
- **美味しそうなご褒美の寄り:** 暖かい光、ハイライト、影、質感（麺線・霜降り・焦げ目）、飲み物（ビールなど）で乾杯を感じさせる
- **季節の描写:** 晩秋は紅葉・カラマツ、冬は雪・雪をかぶったモミ、春は桜、夏は青葉
- **乱数は `ctx.L.rng(seed)` のみ**（毎回同じ絵になるように。`Math.random` は使わない）
